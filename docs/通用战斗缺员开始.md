# 通用战斗缺员开始与峰值周期报酬

全局选项“允许缺员开始作战”默认NO，适用于所有复用通用战斗的玩法。开启时识别“还有可部署的武装小组”提示，再通过OCR识别并点击“确认”，不尝试补齐剩余槽位。确认未生效时重新识别提示；确认后等待胜利或失败结算，上限与原开始作战节点相同，为2000000ms。

关闭时保留上游原有取消提示、选择部署位和部署人形的流程。不添加自动补齐功能、尝试计数、失败处理子选项或停止任务分支。无人形时仍走上游原有初始部署；本次没有修复其颜色识别误点问题，建议先手动配置队伍。

使用Project Interface的global_option将设置应用到各任务，不依赖启动任务是否勾选。原部署位颜色识别、部署动作、自动战斗及结算节点保持不变；缺员确认是通用提示后的可选分支。

峰值推定没有自动弹出报酬时，切换到常规峰值，识别并打开“周期报酬”，复用现有领取和关闭流程；仍兼容自动弹出报酬。PC点击区域基于1280×720现场画面。

原r3的中文PC缺员确认、战斗等待与报酬入口已获用户实机反馈；本次通用开关及英文尚未实机验证。本地使用MaaFramework 5.12.3的离线控制器完成9项回归：关闭恢复原流程、开启不补齐、空队伍初始部署、确认重试、失败结算、等待胜利及三种报酬窗口路径；识别和输入均模拟。三种资源组合加载通过。测试仅保留本地，不随PR提交，check.yml保持原有资源检查。
