# PC 分辨率校验

PC 资源以 `1280×720` 为识别坐标系。两个桌面控制器显式设置
`display_short_side: 720`，由 MaaFramework 等比例缩放截图，并把点击坐标映射回
游戏的原始尺寸。无需为每一种 16:9 分辨率另做一套模板，也不会修改游戏设置。

## 使用方法

1. 更新包含本次 Agent 和资源的完整安装包。只更新 JSON 资源不够。
2. 启动游戏，选择桌面控制器和“中文资源(PC端)”。
3. 在游戏的图像设置中选择合适的 16:9 分辨率。保持窗口可截图，运行期间不要改变分辨率。
4. 每个 PC 游戏任务都会先校验。也可只勾选“检查 PC 分辨率”后开始，该任务只截图，
   不点击游戏、不领取奖励、不执行日常。此选项默认不勾选，不影响普通任务的自动校验。

检查的是截图中游戏客户区的实际尺寸，不是显示器分辨率、Windows 缩放比例或包含标题栏的窗口尺寸。

| 游戏实际尺寸 | 校验结果 |
| --- | --- |
| 1280×720、1600×900、1920×1080、2560×1440、3840×2160 | 可归一到 1280×720，允许执行 |
| 960×540 等低于 1280×720 的尺寸 | 拒绝，避免小图放大丢失识别细节 |
| 1920×1200、2560×1600 等 16:10 | 拒绝 |
| 超宽屏、竖屏、1360×768、1366×768 | 拒绝 |
| 原始尺寸或自定义缩放导致识别截图不是 1280×720 | 拒绝 |

对于接近 16:9 的尺寸，按短边 720 缩放后，长边四舍五入必须恰为 1280，且实际
识别截图也必须为 1280×720。不会把错误比例强制拉伸到标准尺寸。

## 失败后如何恢复

校验失败会在运行日志中显示红色提示，包含原始尺寸、识别尺寸、原因和修复建议，
并停止当前任务及已排队任务。例如：

> PC 分辨率校验失败，任务已停止。游戏截图：1920×1200；识别截图：1152×720。
> 游戏需使用缩放后为 1280×720 的 16:9 分辨率。

修改游戏分辨率后重新开始即可，不需要重启助手。若无法截图，先恢复最小化的游戏窗口，
检查截图方式和权限；若识别截图大小错误，恢复 PC 控制器的短边 720 设置。
截图失败最多重试三次，确认尺寸错误时直接停止。

此检查只验证截图尺寸，不能判断画面是否被其他窗口遮挡、是否处于黑屏加载阶段、
是否选择了正确游戏窗口，也不能保证所有任务在各尺寸下都已适配。前台模式仍需保持
游戏可见；窗口选择校验是独立功能。遇到特定页面字体或布局差异，可暂回到 1280×720。

## 实现与验证

参考 [MaaEnd 的分辨率检查](https://github.com/MaaEnd/MaaEnd/blob/ad2a45af456b0ed5ebed4670baaed5c53ac1db6e/agent/go-service/taskersink/aspectratio/checker.go)
的“新截图、原始尺寸、归一后尺寸”检查思路。本项目使用同步 Custom Action 作为任务入口，
不依赖异步 Agent 事件通知来阻止首个游戏动作。

任务名和选项不变。`assets/tasks` 中的游戏任务先进入 `ResolutionCheck_` 节点，
base 资源中的入口只执行 DoNothing 后进入原任务，PC 资源将该入口覆盖为校验动作。
因此模拟器/原生安卓不增加截图要求；社区任务及 MXU 前置程序保持原入口。
新增游戏任务时也应添加对应入口，资源契约测试会检查遗漏。

校验失败时 Custom Action 返回失败，禁止进入原任务，同时调用 `post_stop()` 清空队列。
回调内不等待停止完成，避免等待自身造成死锁。每个任务都重新截图，避免读取游戏
切换分辨率之前的缓存。一个任务内部进行中途缩放需等下一任务才会重新校验。

运行回归测试：

```shell
python -m unittest discover -s tests -v
python check_resource.py
```

测试覆盖尺寸边界、截图失败及恢复、双语提示、所有游戏入口、模拟器入口、原生框架
坐标映射、当前与排队任务中止，以及独立 Agent 进程的同步拦截。测试控制器仅记录输入，
不会向系统窗口或模拟器发送点击。开发依赖中的 MaaFramework 5.4.1 也可运行本地测试；
TCP Agent 夹具需要较新的框架，旧版会跳过该项。

国服 PC 实测的范围是只读分辨率检查与主页 OCR，不包含完整日常、战斗或所有模板适配。
