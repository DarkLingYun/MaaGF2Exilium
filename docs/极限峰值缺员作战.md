# 极限峰值缺员作战与周期报酬

模拟作战日常新增“极限峰值：槽位未满仍开始作战”，默认NO。YES只改变极限峰值0级三个子群的部署流程；其他模式仍沿用原有补人逻辑。未部署任何人形时仍先部署人形；识别到“还有可部署的武装小组”后才识别并点击“确认”，不使用固定坐标确认。

部署位识别、自动部署、自动战斗及结算全部复用通用战斗节点。三个子群通过锚点启用共享文件中的缺员确认分支；返回极限峰值标签页或结束任务时清除锚点。通用缺员提示识别后才查询该分支，未启用时继续原有取消补人路径，不复制整套战斗节点。锚点需要MaaFramework 5.7或更新版本。

缺员确认节点采用与原开始作战节点相同的timeout=2000000。自动战斗已经开启时，等待胜利或失败结算，避免因为无法匹配“自动战斗_off”而在默认20秒后提前结束。

峰值推定没有自动弹出报酬时，切换到常规峰值，识别左下“周期报酬”并打开，复用现有领取和关闭流程；仍兼容自动弹出报酬。PC点击区域基于1280×720现场画面，未通过红点推断已领取。

中文PC实机反馈已确认原r3的缺员确认、战斗等待与切页打开报酬流程；复用通用节点后的重构尚未重新实机验证。英文提示沿用现有翻译，尚无英文实机验证。离线回归使用MaaFramework 5.12.3模拟识别和输入，验证14项路由及选项隔离；资源加载与实机效果是不同证据。该框架在未设置锚点时可能记录node not exist，但会继续识别后续取消节点；关闭选项、普通战斗及同任务离开峰值后的回归均覆盖此路径。

开发验证依赖：`pip install maafw==5.12.3 json5 numpy`。验证入口：`python -m unittest discover -s tests -v`、`python check_resource.py`。测试使用自定义离线控制器，真实输入调用会直接失败，不连接或操作游戏。离线路由测试仅在开发时运行，check.yml保持原有资源加载检查。
