# 通用战斗部署策略与峰值周期报酬

全局选项“启用通用战斗部署策略”适用于所有复用通用战斗的玩法，默认NO；关闭时保留原有取消提示、补人再开始的行为。使用Project Interface的global_option，参数会应用到每个任务，不依赖启动任务是否勾选。仅把选项挂在启动任务上不会影响后续战斗。

开启后，“开始作战前优先补齐”默认YES，沿用现有部署位颜色识别和人形选择。识别具体缺员提示后最多进行6次补齐尝试，每次进入通用战斗重置。找不到部署位或部署按钮时，经过3秒识别等待转到失败处理，避免反复尝试；无法重新识别开始作战按钮时停止当前任务。

“无法补齐时”默认“缺员强行开始”，也可选择“取消并停止当前任务”。继续时先确认具体缺员提示，再通过OCR识别并点击确认；等待胜利或失败结算的上限与原开始作战节点相同，为2000000ms。停止时取消提示并停止当前任务，保留游戏，不会重复开始；界面可能仍留在部署页，需用户检查。

选择不补齐时直接使用缺员确认，忽略之前保存的失败处理选择。没有部署任何人形时仍先尝试部署至少一人。GUI对不适用的子选项采用隐藏方式，不能仅靠interface配置显示灰色控件；隐藏的子选项不参与覆盖。部署、自动战斗与结算复用原节点，六个尝试节点只负责记录有限尝试的路由，不复制部署实现。锚点需要MaaFramework 5.7或更新版本。

峰值推定没有自动弹出报酬时，切换到常规峰值，识别并打开“周期报酬”，复用现有领取和关闭流程；仍兼容自动弹出报酬。PC点击区域基于1280×720现场画面。

原r3的中文PC缺员确认、战斗等待与报酬入口已获用户实机反馈；本次通用部署策略和英文均未重新实机验证。本地使用MaaFramework 5.12.3的离线控制器完成14项路由回归，包括失败补齐的两个分支、不补齐时忽略旧子选项、每场重置计数及等待结算；识别和输入均模拟。三种资源组合加载通过。测试脚本不随PR提交，check.yml保持原有资源检查。
